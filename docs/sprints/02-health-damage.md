## 목표

**"맞으면 죽는다"를 "체력이 깎이고 0이 되면 죽는다"로 바꾼다.**

지금은 플레이어 공격이 적을 즉시 `Destroy()`하고, 적의 접촉 공격은 스텁(`EnemyMove.TryAttack()`이 비어 있음)이라
플레이어가 죽지 않는다. 이 스프린트가 끝나면 양쪽 모두 실제 체력을 갖고 서로 피해를 주고받는다.

이게 최우선인 이유: 보상(골드/경험치)·런 종료·엘리트/보스·원소·아이템 스탯이 **전부 체력에 의존**한다.

## 범위 — 이번에 만드는 것

1. `Core/IDamageable` — 피격 가능 대상 인터페이스
2. `Enemies/EnemyHealth` — 적 체력, 피격 플래시, 넉백, 사망
3. `Characters/PlayerHealth` — 플레이어 체력, 무적시간, 피격 반동, 사망 신호
4. 공격 스크립트를 `Destroy()` 직접 호출 → `IDamageable.TakeDamage()` 호출로 전환
5. 접촉 데미지 활성화 (`EnemyMove.TryAttack()` 스텁 채우기)
6. 치명타 판정

### 데미지 계산식
원본(`:1664`)에서 **이번 스프린트 범위에 해당하는 항만** 남긴 것:

```
dmg = max(1, round( atk × 무기배수 × 차지배수 × rand(0.9, 1.1) × (치명타면 1.7) ))
```

- `rand(0.9, 1.1)` — 원본에 있는 ±10% 난수 변동(`:983`, `:1664`). **빠뜨리지 말 것**
- `max(1, ...)` — 최소 피해 1 보장
- `round(...)` — 정수 피해

제외한 항(범위 밖): `dmgMultAll()`(콤보·살기·아이템·성소) · `vulnMult` · `lvF`(레벨 페널티) · `itemDmgVs` · `rebirthWallPlayerDmgMult`

### 스폰 무적
- 원본은 `dealDamage` 진입 즉시 `if (e.spawnInvuln > 0) return 0;` — **피해가 0이고 관통도 소모되지 않는다**(`:1659`)
- **검사는 두 곳 모두에 있어야 한다**(구현하며 확인됨): 공격 스크립트(`MageProjectile`) 쪽 검사는 *관통 카운트를 소모하지 않기 위한* 것이고, `TakeDamage()` 쪽 검사는 *어떤 경로로 들어온 피해든 무효화하기 위한* 것이라 역할이 다르다. 한쪽으로 합치면 둘 중 하나가 깨진다.
- 원본은 스폰 보호 중 적 갱신을 통째로 건너뛴다 — **"상호 무적: 움직이지도, 때리지도, 맞지도 않는다"**(`:4022~4023`). 기존 `EnemyMove`는 타이머만 깎고 이동·접촉을 계속해서 무적인 몹이 플레이어를 때릴 수 있었다(원본과 다름) → 이번 스프린트에서 같이 수정.

### 접촉 데미지
- 원본은 매 프레임 겹침 검사 후 `damagePlayer(e.dmg, e.x)` 호출, **별도 쿨다운 없음**(`:4148`)
- 반복 피해 방지는 **플레이어 무적시간(0.9초)이 전담** — 적 쪽에 쿨다운을 넣지 말 것
- 조건: `player.invuln <= 0`일 때만(`:4144`)

## 구현 시 주의점

**넉백과 기존 이동 로직의 충돌** — `EnemyMove.FixedUpdate()`가 매 프레임
`rb.linearVelocity = new Vector2(vx, vy)`로 속도를 통째로 덮어쓴다. 넉백을 그냥 속도에 넣으면 다음 프레임에
즉시 지워진다. 원본은 넉백을 **별도 성분**으로 두고 AI 이동에 더한다(`e.x += (e.vx + e.kbx) * dt`, `:4056`).
같은 방식으로 `knockbackX` 필드를 따로 두고 매 프레임 감쇠시킨 뒤 `vx`에 더할 것.

**도메인 계층** — `IDamageable`은 `Core`, 구현체는 각자 도메인(`Characters`/`Enemies`).
공격 스크립트(`Combat`/`Characters`)는 `Enemies` 타입을 몰라야 하므로 반드시 `Core` 인터페이스로만 접근한다
(`ISpawnProtectable`과 같은 원리, `CLAUDE.md` asmdef 계층표 참고).

**플레이어 사망** — 런 종료는 스프린트 3 범위다. 이번엔 `PlayerHealth`가 사망 상태/이벤트만 노출하고,
받는 쪽은 만들지 않는다(빈 채로 두되 나중에 `Systems`가 구독할 수 있는 형태로).

## 검증 기준

PlayMode 테스트로 다음을 확인한다(기존 20개 + 신규):

- 적이 한 방에 안 죽는다 — 체력 38, 무차지 마법탄(9±10%)으로 여러 번 맞아야 죽음
- 체력이 0 이하가 되면 파괴된다
- 스폰 무적 중엔 피해가 0이고 관통도 소모되지 않는다
- 플레이어가 적과 접촉하면 체력이 13만큼(±10%) 깎인다
- 피격 후 0.9초 동안은 다시 안 깎인다(무적시간)
- 피격 시 가해자 반대 방향으로 밀려나고 위로 튕긴다
- 치명타가 통계적으로 발생한다(난수 고정 또는 반복 시행으로 검증)
- 넉백이 적용되고 감쇠한다

**기존 20개 테스트가 전부 통과해야 병합한다**(`CLAUDE.md` 테스트 규칙).

구현하며 원본을 다시 읽고 **스펙과 달라진 판단 2건**(둘 다 원본 확인 후 결정):

1. **플레이어 수평 넉백은 유지하지 않는다.** 원본은 `p.vx = sign × 260`을 넣지만 바로 다음 프레임
   `p.vx = mx * moveSpeed`가 통째로 덮어쓴다(`:1548`, 피격 중 이동 잠금이 없음 — `lockMove`는 공격 전용).
   즉 원본에서도 수평 넉백은 실질적으로 1프레임짜리다. 우리 `CharacterMover2D`도 매 FixedUpdate에 vx를
   덮어쓰므로 **아무 처리도 안 하는 게 원본과 같다** — 적처럼 감쇠형 넉백을 넣으면 오히려 원본보다 세진다.
   (수직 튕김은 vy를 보존하므로 그대로 남는다.)
2. **적 넉백은 반대로 별도 성분이 필수다.** 원본 `e.kbx`는 AI 속도에 *더해지는* 값이고 초당 9배율로
   감쇠한다(`:4021`, `:4056`). 그냥 속도에 넣으면 `EnemyMove.FixedUpdate`가 다음 프레임에 지워버린다.

기존 테스트 중 4건은 "한 방에 파괴"를 전제로 짜여 있어 새 동작(체력 경유)에 맞게 갱신했다 —
각 테스트가 원래 검증하던 것(사거리·태그 필터, 관통 횟수, 스폰 무적)은 그대로 두고 기대값만 바꿨다.
