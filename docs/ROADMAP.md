## 1. 원본 시스템 전수 목록

원본은 단일 HTML 파일이지만 내부적으로는 명확히 **메타 루프 / 런 루프 / 전투 / 성장 / 연출** 다섯 덩어리로 나뉜다.

### 1-1. 씬(화면) 구조
`state.scene`(`:1465`)이 전체를 지배하는 4상태 머신이다.

| 상태 | 내용 |
|---|---|
| `lobby` | 로비. 6개 탭(스테이지·강화·전문화·윤회·업적·가챠) |
| `run` | 실제 사냥(전투) |
| `pause` | 일시정지(`:4332`) |
| `result` | 런 종료 결과창(`:4354`) |

로비 탭별 렌더 함수: `renderStageTab`(`:6441`) · `renderUpgradeTab`(`:6473`) · `renderSpecTab`(`:6971`) · `renderRebirthTab`(`:6902`) · `renderAchieveTab`(`:6888`) · 가챠(`:6542~6873`).

### 1-2. 런(사냥) 루프
`startRun`(`:4293`) → `updateRun`(`:4409`) → `endRun`(`:4354`) → `toLobby`(`:4382`).

- **입장료**: 지역별 골드, 지수 증가(`entryFee: base 300, grow 2.2`, `:739`). 1지역 무료
- **제한시간**: 일반 90초 / 보스 180초(`CONFIG.run`, `:695`)
- **종료 사유**: `dead` / `timeout` / `bossdead`
- **일반 모드**: 3.6초마다 웨이브 7마리, 필드 상한 22마리, 성소는 18초 후 첫 등장·이후 35초 간격(`:698`)
- **보스 모드**: 미니언 7초마다 2마리, 최대 4마리 유지
- **지역 진행**: 지역 누적 100킬(`regionKillTarget`, `:699`) → 보스 해금(`:1866~1869`) → 보스 처치 시 다음 지역 개방

### 1-3. 전투 코어
- **데미지 파이프라인**: `dealDamage`(`:1657`) — 치명타, 레벨 페널티, 원소, 아이템 상황부 배수를 전부 여기서 합산
- **배수 체인**: `dmgMultAll`(`:1296`) = 콤보 × 살기(fury) × 아이템 × 성소 × 상황부
- **플레이어 피격**: `damagePlayer`(`:1879`) — 무적시간 0.9초(`:606`), 부활/피격무효 아이템 처리
- **처치 처리**: `killEnemy`(`:1793`) — 골드·경험치·혼 드랍, 연쇄 처치 보너스, 분열귀 분열(`:1840`)
- **원소**(`:691~694`, `applyElement` `:1699`): 화상(burn, 10스택, 지속피해) / 출혈(bleed, 10스택 + 체력 비율 이하 즉시 처형)
- **연출**: hitstop(`:743`), 화면 흔들림, 슬로모(연쇄 처치 `:704`), 데미지 팝업, 파티클

### 1-6. 성장 3계층
원본 설계의 핵심. **의도적으로 세 층이 서로 다른 주기로 리셋된다.**

| 계층 | 내용 | 리셋 시점 | 원본 |
|---|---|---|---|
| 1. 레벨/경험치 | 런 중 획득. 몹 레벨보다 낮으면 **딜 페널티**(레벨당 -5%, 하한 25%) | 윤회 시 | `:706`, `:729` |
| 2. 골드 강화 | atk/hp/ms/as/crit 5축, **선형** 증가 | 윤회 시 | `:731~737`, `buyGoldUpgrade` `:7042` |
| 3. 아이템 35종 | 가챠로만 획득, **영구** | 절대 안 됨 | `ITEMS` `:759` |

- **최종 스탯 계산**: `statAtk`/`statMaxHp`/`statMs`/`statAs`/`statCrit`(`:1284~1288`) = (기본 + 골드강화 + 아이템) × 캐릭터 배수
- **의도된 벽**: 몹은 지역당 지수(hp ×2.15) 성장 vs 골드강화는 선형 → 5지역쯤 막힘 → 윤회 강제(`:727`, `:730` 주석)

### 1-7. 윤회(프레스티지) + 가챠
- **윤회**(`doRebirth` `:6509`): 클리어한 지역 수 → RP 획득(1·2·5·9·15·21·29·38·48). 레벨·골드·강화·지역진행 초기화, 아이템·RP 유지
- **윤회 장벽**(`:741`): 지역별 권장 윤회 횟수(`regionReqRebirth` `:973`) 미달 시 적 hp×2.8 dmg×1.45, 내 딜 ×0.62
- **가챠**(`doGacha` `:6572`): RP 소모, 등급 가중치(common 55 / rare 30 / epic 12 / legend 3, `:750~755`), 천장 카운터(`meta.pity`), 등급별 중복 상한

### 1-8. 세이브
`meta` 단일 객체(`defaultMeta` `:1129`)를 `localStorage`에 JSON 통째로 저장(`:1213~1214`).

## 3. 의존성 분석 — 왜 순서가 중요한가

각 시스템이 뭘 전제로 하는지 따져보면 순서가 거의 강제된다.

```
Health/데미지  ←── 거의 모든 것의 뿌리
   ├─ 몹 처치 판정 → 골드/경험치 보상
   ├─ 플레이어 사망 → 런 종료 조건
   ├─ 원소(화상/출혈) — 지속 피해가 필요
   ├─ 엘리트/보스 — hp 배수가 의미를 가지려면 hp가 있어야
   └─ 아이템 atk/hp 스탯 — 스탯 시스템 자체가 필요

런 사이클(제한시간·종료·결과)
   └─ 보상 정산 → 성장 루프의 입구

세이브(PlayerProfile)
   └─ 로비·강화·윤회·가챠 전부가 "저장되는 진행"을 전제

로비 UI
   └─ 강화·전문화·윤회·가챠의 유일한 접점
```

**결론: `Health` → `런 사이클` → `세이브` → `로비/강화` 순서가 사실상 고정.**
이 넷이 끝나면 "사냥 → 보상 → 강화 → 더 강한 사냥"이라는 **게임의 최소 완결 루프**가 성립한다.
지금은 이 루프가 없어서, 아무리 전투를 다듬어도 "플레이할 수 있는 게임"이 되지 않는다.

## 4. 권장 스프린트 순서

### 스프린트 2 — 체력 & 데미지 ✅ **완료(2026-09-03, PlayMode 30/30)**
> 확정 스펙과 구현 결과는 `HANDOFF.md` 참고. 아래는 착수 시점의 계획이다.

**이게 없으면 다른 어떤 것도 의미를 못 가진다.**

- `Core/IDamageable` 신설 (CLAUDE.md "데미지/피격 인터페이스" 규칙에 이미 설계돼 있음, 아직 미구현)
- `Characters/PlayerHealth`, `Enemies/EnemyHealth` — 둘 다 `IDamageable` 구현
- 공격 스크립트를 `Destroy()` 직접 호출 → `TakeDamage()` 호출로 전환 (`MageProjectile`, `PlayerAttack`)
- 플레이어 피격: 접촉 데미지 활성화(`EnemyMove.TryAttack()`의 스텁 채우기) + 무적시간 0.9초(`:606`)
- 치명타(기본 10%, 배수 1.7, `:605`)
- 원본 참조: `dealDamage`(`:1657`), `damagePlayer`(`:1879`), `killEnemy`(`:1793`)
- **도메인**: `Core`(인터페이스) + `Characters`/`Enemies`(구현) — 계층 위반 없음
- **리스크**: 낮음. 기존 구조와 충돌 없음

### 스프린트 3 — 런 사이클 & 보상
- 제한시간 90초, 종료 사유 3종(`dead`/`timeout`/`clear`), 결과 화면
- 골드·경험치 획득, 레벨업 곡선(`:706`)
- 최소 HUD (체력바·시간·골드) — **여기서 `UI` 도메인이 처음 생긴다**
- 원본 참조: `startRun`(`:4293`), `updateRun`(`:4409`), `endRun`(`:4354`)
- **도메인**: `Systems`(런 상태 관리) + `UI`(HUD) + `Core`(런 데이터)
- **리스크**: 중간. 씬 상태 전환 구조를 처음 도입하는 스프린트라 설계 결정이 몇 개 있음

### 스프린트 4 — 세이브 & 로비 & 골드 강화
- `Core/PlayerProfile` (순수 직렬화 클래스, **SO 아님** — CLAUDE.md "세이브 데이터 vs 설정 데이터" 참고)
- `Systems/SaveSystem` — 파일 입출력
- 로비 씬 + 강화 탭(5축 선형 강화, `:731~737`)
- 여기까지 하면 **"사냥 → 보상 → 강화 → 재도전" 최소 완결 루프 완성**
- 원본 참조: `defaultMeta`(`:1129`), `buyGoldUpgrade`(`:7042`), `renderUpgradeTab`(`:6473`)
- **리스크**: 중간. 세이브 스키마를 처음 정하는 시점이라 나중에 필드가 계속 추가된다는 걸 전제로 설계해야 함

## 5. 지금 결정이 필요한 것 (사용자 확인 필요)

1. **위 순서대로 갈지** — 특히 "체력 → 런 사이클 → 세이브/로비"를 먼저 하고 전투 다양성(캐릭터·몹)은 나중으로 미루는 판단에 동의하는지.
   - 대안: "재미부터 확인하고 싶다"면 스프린트 2(체력) 후 바로 6(몹 종류)로 건너뛸 수도 있다. 대신 게임 루프는 계속 없는 상태로 남는다.
2. **AI 기능을 어디에 넣을지** — 논의된 후보(윤회 회고 텍스트 / 웨이브 디렉터 / 보스 페이즈 전략)는 전부 스프린트 7 이후 시스템에 붙는다. 지금 로드맵엔 반영하지 않았다.
3. **UI 방향** — 원본은 HTML/CSS로 로비를 그렸다. Unity에선 uGUI / UI Toolkit 중 뭘 쓸지 스프린트 3 시작 전에 정해야 한다.
4. **연출 수준** — 원본은 hitstop·화면흔들림·파티클·슬로모가 촘촘히 들어가 있다. "원본 그대로" 원칙을 연출까지 적용할지, 기능 우선으로 미룰지.
