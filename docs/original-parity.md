# 원본(프로토타입) ↔ Unity 이식 대조표

원본 `reference/project_test.html`(7199줄)과 현재 Unity 구현(`Assets/Scripts`, 30파일 2636줄)을
시스템 단위로 전부 대조한 결과. **비주얼(캐릭터/몹/배경 그림, 파티클, 렌더링 1734줄)은 대조 대상에서
제외** — 사용자 확인 사항(2026-09-08): "캐릭터나 배경 이런 건 달라도 상관없는데 게임 내부 동작은 다 돼야 한다".

작성 2026-09-08, **갱신 2026-09-10**. 숫자 뒤 `:NNNN`은 전부 원본 줄 번호.

> ⚠️ 이 문서는 **대조표(무엇이 다른가)**이지 할 일 목록이 아니다. 현재 스프린트는 루트 `HANDOFF.md`,

## 0. ✅ 해결됨 — 게임의 뼈대 (2026-09-10)

09-08 시점의 "가장 큰 문제"였다. 원본은 **로비 ↔ 사냥(런) ↔ 결과**를 오가는 게임인데 우리는
**끝없이 이어지는 전투 씬 하나**뿐이었고, 그래서 임시방편(R키 부활·인게임 숫자키 강화)이 쌓여 있었다.

| | 원본 | 우리 (2026-09-10) |

| 씬 상태 | `state.scene` 4종 (`:1466`) | ✅ `Core/GameState` |
| 사냥 시간 | 일반 90초 · 보스 180초 (`:695`, `:4412`) | ✅ `RunState` + `RunController` (보스전은 모드만 존재) |
| 죽으면 | 결과 화면 → 로비 (`:1927`) | ✅ 동일. **R키 부활 삭제됨** |

## 4. 전투 배수 체인 (통째로 없음)

원본 `dealDamage`(`:1664`)의 최종 피해식은
`statAtk × dmgMultAll() × mult × vulnMult × lvF × itemDmgVs × rebirthWall × rand(0.9,1.1) × crit`.
**대상과 무관한 항은 `Combat/DamageCalculator`, 대상에 달린 항은 `Enemies/EnemyHealth`가 곱한다**
(계산기가 대상 참조를 갖지 않는 순수 함수라서). 수치는 `Core/CombatModifiers`에 모여 있다.

- [x] **콤보** — 3초 윈도우, 콤보당 피해 +1.2% / 골드 +0.8% (`:742`, `:703`, `:1621`)
- [x] **살기(fury)** — 런 내 처치마다 피해 +0.8% / 공속 +0.4% 누적 (`:702`, `:1825`)
- [x] **연쇄 처치** — 0.8초 내 3킬 이상 시 골드 보너스 (`:704`, `:1829`). 슬로모 연출은 없음
- [x] **레벨 페널티** — 내 레벨 < 몹 레벨이면 레벨당 -5%, 하한 25% (`levelFactor`, `:729`, `:1651`)
- [x] **성소 버프 수신** — 피해 ×1.3, 이속 ×1.25 (`:1300`). **거는 쪽(성소)이 아직 없다**
- [x] **취약(vulnT)** — 중력점 장기 노출 시 받는 피해 ×1.2 (`:1663`, `:3817`). 아이템 경로는 없음
- [x] 히트스톱(`state.freeze`) — `RunController.Hitstop()`. 지속 피해 틱엔 안 걸린다(`:1686`)
- [ ] 아이템 항 전부 — `itemMul('dmg')`, `itemDmgVs`, `lastStand`, `airDmg` (6절이 먼저 필요)
- [ ] 윤회 장벽 `rebirthWallPlayerDmgMult` (6절이 먼저 필요)

> ⚠️ **살기·공속**: `CombatModifiers.AttackSpeedMultiplier`가 계산은 하지만 **아직 아무 공격
> 스크립트도 그걸 곱하지 않는다** — 캐릭터 키트가 쿨다운을 계산할 때 넣어야 한다(섬영·드루이드 포함).
